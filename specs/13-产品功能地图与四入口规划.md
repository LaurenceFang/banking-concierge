# 银小二：四入口、功能地图与共享对话（规划草案）

日期：2026-10-13。状态：功能地图已认可，核心实现见SPEC15，后续能力仍为规划。本稿替代此前六入口草案。用户最新方向：账户、账单、财富、生活四个一级入口；收付款并入账单，安排并入生活；主对话默认可问任何事，普通对话在主页全局左栏与业务页按二级范围筛选的左栏共享；正文不设相关对话区。

四入口v2样稿现已获用户认可，核心工作区完成情况见[实施状态](15-四入口工作区实施状态.md)。下文是完整功能地图，仍含后续与远期能力；旧P3-B三张图不作为实施目标，相关新业务入口未开放。

## 1. 规模与边界

业务能力从原48组重新归并为 **36组：账户8、账单10、财富8、生活10**，原有子能力全部保留映射。另有8组共用交互与4组设置支持，共48组产品能力。组数是本版规划的组织口径，不是按钮、页面、后台模块或完成项的数量。

每个一级入口规划4个二级页，总计16个；8–10组业务能力分布在这4页及其详情中，不做成8–10个页签。未实现的远期页面不提前展示。数量是控制复杂度的约束，不为凑数增加功能，也不把后续候选全部变成本届比赛承诺。

状态沿用之前的功能盘点：已有=相应旧能力已存在，新子页未实现；部分=覆盖不全；草稿=P3-B未提交且集成未完成；规划=尚未实现的新组织与交互；后续=候选；远期=仅预留归属。本稿未重新运行业务验收。模拟申卡受理不等于发卡；固定生日流程不等于通用多步规划。

## 2. 四个一级入口与16个二级页

左侧上方保留固定“主对话”和“对话”列表，左下业务区固定四项，建议2×2。设置、通知偏好和帮助沿用头像菜单。新能力归入四类，不增加“更多”或第五个业务入口。

| 一级入口 | 用户来这里做什么 | 二级页 | 功能组 |
|---|---|---|---:|
| 账户 | 看和管理自己的账户、卡、借贷关系 | 资金总览、资金账户、银行卡、借贷 | 8 |
| 账单 | 查收支，也能发起和跟踪收付款 | 收支明细、收付款、分析与预算、导入整理 | 10 |
| 财富 | 看产品、持仓、投资计划和申赎结果 | 持仓与计划、产品比较、订单、风险档案 | 8 |
| 生活 | 管订阅、缴费、生活服务和要办的事 | 我的安排、订阅与缴费、生活服务、日历 | 10 |

这里“账单”承担较宽的收支管理含义。进入后要清楚看见“收付款”，避免用户以为这里只能看历史；首页可直接提供“转账”“收款”快捷动作，它们仍归同一子页，不成为新一级入口。

### 子页布局与职责

点击一级入口直接进入第一个已实现二级页并展开左栏，不增加中间目录选择页、不先隐藏再弹出。默认页放在二级导航首位；切换其他页签同步更新左栏对话范围。正文只按“标题与主动作 → 必要摘要 → 对象列表或详情”排列，不设置相关对话区域。主页左栏显示全部普通对话，业务页左栏只显示当前二级范围对话；顶部固定主对话，底部四入口和个人菜单保持。银小二旁主页图标返回主页面。对象操作放在详情，状态用筛选表达。

| 入口／默认页 | 二级页 | 页面重点 | 内部安排 |
|---|---|---|---|
| 账户／资金总览 | 资金总览 | 账面、可用、预留及对应来源 | 资金变化链接到账单；预留链接到原安排 |
| 账户 | 资金账户 | 账户列表、详情和默认收付账户 | 账户绑定属于后续能力；每个账户可就此讨论 |
| 账户 | 银行卡 | 卡片、额度、状态和申请记录 | 冻结、解锁、挂失等在卡详情办理 |

| 财富 | 持仓与计划 | 持仓、份额、目标与投资计划 | 赎回在持仓详情；定投等后续能力逐项建设 |
| 财富 | 订单 | 申赎受理、结算和到账状态 | 订单详情关联回执和原对话 |

| 生活／我的安排 | 订阅与缴费 | 订阅合同、候选、费用和续费日 | 订阅与日常缴费用页内分组，不平铺所有操作 |

| 生活 | 我的安排 | 待处理、进行中、已安排和历史事项 | 详情展示方案、步骤、预算和授权；对话由左栏进入 |
| 生活 | 日历 | 提醒、待确认事项与已授权执行 | 状态明确区分；点击进入原业务对象或安排 |

空状态不改变默认页位置。借贷等未建设页面只保留在规划中，不做空壳承诺。左栏的按业务范围显示对话是同一套共用能力，不额外计入36组业务功能。

## 4. 主对话与普通对话

### 默认打开主对话：Anything you can ask

主对话既能日常提问，也能讨论复杂问题或提出办理需求，不限定为通知收件箱。助手根据问题选择：

- 能直接答就答：余额、某笔支出、知识解释等，不强制展示入口卡。
- 适合看页面时，回答后附“查看账单”“打开账户”等入口；已有明确对象就直达二级页或对象详情，并显示归属路径。
- 可以在原对话完成的办理，直接补齐信息并提供相应确认，不强迫进入表单。
- 用户希望单独展开时，提供“另开对话继续”；只有用户选择或主动新建才转入新对话。原问题上下文可带入，无须重复输入。

点击入口卡才导航；仅识别出业务类型不自动抢占页面，也不默认新建对话。主对话可以讨论任何业务；用户正在普通对话中时，也不因话题跨域就自动拆分。

固定主对话显示在左侧独立位置。其余统一称“对话”，不再使用“临时对话／临时事项”作为用户界面名称。

### 正常收支自动告诉用户

实际到账、实际支出、办理结果、待处理和到期提醒可以主动写入主对话。通知来自实际业务事件，金额、账户、时间及结果取自业务记录；模型可解释，不能自己猜有一笔新收入。

同一事件重试不重复通知，连续低优先级事件可汇总；与原对话有关的结果同步显示在那里。用户正在别处时只更新未读状态，不强制切回主对话或展开面板。通知可提供“查看明细”“继续原对话”。资金预留、待收AA、预计续费分别说清状态，不写成已经扣款或到账。外部支付宝等渠道需要实际接入后才能提供对应通知，目前不宣称已连接。

## 5. 一条对话、左栏的全局与业务范围

**只有一处左侧对话列表：主页显示全部，业务页按当前二级页面筛选。同一条记录在不同范围下可见，消息不复制；正文不再另放历史列表。**

| 从哪里发起／打开 | 行为 | 左侧与子页怎样同步 |
|---|---|---|
| 左侧点新建对话 | 首次发送时保存普通对话 | 主页不预设业务分类；业务页默认关联当前二级范围 |
| 账户→借贷→左栏新建 | 带上借贷范围或选中的借贷对象 | 首次发送后在当前范围左栏可见；回主页仍可见同一记录 |
| 业务页左栏点历史对话 | 保留业务页，右侧恢复原对话与草稿 | 沿用同一ID，不新建副本 |
| 主页左栏点同一条对话 | 在中央打开完整对话 | 消息、标题、业务草稿与业务范围下完全一致 |
| 主对话点击业务入口 | 浏览对应页面 | 不凭浏览动作创建普通对话 |
| 子页来自某条对话的跳转 | 提供“继续原对话”，也可另开 | 继续时沿用原对话；另开时明确新主题 |
| 对话涉及多个业务 | 保持一条对话，可关联多个范围 | 左侧只显示一项，多个相关子页都能找到 |
| 重命名、归档、删除对话 | 操作同一记录，作用范围明确 | 所有索引同步；仅解除某页关联不等于全局删除 |

“账户→借贷”的对话例子用于解释结构，借贷业务本身仍是远期规划。

### 对话如何归类

1. 子页发起：子页范围是默认主分类；选中的对象作为显式上下文。首条消息发出前不生成空历史。
2. 在主页从左侧新建：可先无分类；形成明确主题或引用实际业务对象后自动关联。仅提到“银行卡”三个字不够触发归类。
3. 跨场景：保留一个主分类和多个相关分类。例如生日安排可同时出现在生活／我的安排、生活／生活服务以及有实际付款关联的账单／收付款。
4. 用户可改分类、移除关联。其修正不能被后续自动分类立即覆盖；无法确定时可暂不归类，仍从全局列表找得到。
5. 业务页左栏显示当前二级范围的普通对话；对象详情为讨论提供上下文，不静默进一步改变左栏范围。按最近活动排序，提供搜索，不为历史数量增加导航层级。
6. 主对话不在每个子页重复成一整条历史。若相关讨论发生于主对话，可显示“主对话中的相关讨论”定位链接，点击回到对应消息段；不把整条主对话当作该页专属聊天。

业务页需要保存的是对话关联关系，不应各自维护一套独立聊天存储。左栏全局与二级范围引用同一会话及消息，只是筛选条件不同。快速切页时迟到的旧列表响应不能覆盖当前范围。

## 6. 工作区、对话与动作面板

桌面保留左侧导航和一个中央工作区；右侧面板按需出现。默认中央是主对话，一级入口切换中央为业务子页，并保留可返回的来源对话。

- 中央为完整对话时，右侧用于对象详情或操作确认，不重复显示另一个相同聊天。
- 中央为子页时，从左栏新建或打开对话可在右侧显示；可以放大为中央完整对话，保留业务范围与返回原子页入口。放大不等于回主页；点击主页图标或固定主对话才恢复全局列表。
- 右侧只有一个槽位。子页聊天产生需要确认的动作时，面板切到确认视图，保留“返回对话”；确认完成后可返回原聊天。
- 新的待确认动作可以自动展开；手动关闭后同一版本不反复打开。后台普通收支通知只更新消息和未读，不抢焦点。
- 关闭面板不取消业务；离开页面保留输入、滚动位置和草稿。正在生成的回复继续写入原对话，不串到新打开的对话。
- 手机按页面切换复用相同数据关系，不硬塞三栏。

聊天与表单编辑同一份业务草稿。修改金额、对象、时间等办理参数才更新版本并让旧确认失效；询问手续费、解释产品等只读讨论不会无故清空确认。执行结果以业务服务返回为准。

## 7. 三条完整用户路径

### 路径一：主对话查收支

打开主对话 → 问“这月花了多少” → 直接给摘要，可点击“账单／分析与预算” → 用户点击才进入页面 → 从当前范围左栏新建对话，首条发送后成为普通对话 → 当前左栏可见，回主页全部列表也能找到同一记录。

随后实际收到一笔款项 → 主对话显示到账通知和“查看明细” → 当前页面保持不动。

### 路径二：账户→借贷→历史对话

进入账户／借贷 → 左栏只显示借贷相关对话 → 点击“提前还款怎么安排”继续上次讨论 → 回主页从全部列表也能打开同一条记录 → 标题与内容同步。

若从借贷页新问一个问题，发送后自动加入两处历史。仅进入借贷页、打开空输入框不创建对话。此路径为未来借贷页的交互示例，不代表当前支持借贷测算或申请。

### 路径三：生日安排跨业务

普通对话提出“给家人安排生日，预算500元” → 生活／我的安排展示同一目标的方案 → 服务订单可从生活／生活服务查看，实际付款可从账单查看 → 对话仍只有一条，可在相关子页找到。

一笔订单失败需要退款 → 原安排显示处理进度，原对话继续讨论 → 实际退款到账后更新账单和主对话通知。不会另外生成花束、蛋糕、付款、退款四条聊天。

## 8. 工程对象与共用能力

四入口是信息组织，不对应四个Agent或四套状态。保留现有业务服务，新增和重整以下共享关系；具体字段、路由与迁移待本规划认可后再冻结契约。

| 对象 | 职责与关系 |
|---|---|
| 对话 | 唯一ID、标题、消息、输入恢复、状态；主对话与普通对话类型明确 |
| 对话关联 | 对话与业务范围／对象的关联，区分主分类、相关分类及用户修正；两处列表共用 |
| 页面上下文 | 当前页、选中对象、筛选范围、来源对话与返回位置；浏览不等于授权或关联新任务 |
| 事项 | 需要持续跟踪的目标、步骤、时间与进度；一条对话可以没有事项，也可关联多个事项 |
| 业务草稿 | 参数、版本、缺失项；对话与表单共同编辑，确认绑定具体操作及版本 |
| 业务对象与事件 | 账户、合同、订单、真实流水等事实；多个视图引用，事件驱动结果与通知 |

对话不是任务，一次问答不是一次业务操作。纯知识问答无需创建事项；多个事项在同一对话讨论时，助手与表单明确当前操作对象，不能把新转账默默挂到旧生日预算上。

| 共用交互ID | 能力 | 本次规划变化 |
|---|---|---|
| C01 | 主对话与主动通知 | 默认万能问答；提供按需跳转；业务事件驱动通知 |
| C02 | 对话、主题与历史恢复 | 去掉临时命名；统一持久记录 |
| C03 | 自然语言查询、RAG知识解释与来源 | 知识库解释规则；实时金额与业务状态由工具读取 |
| C04 | 全局／子页对话索引和页面上下文 | 两处入口同一对话；显式选中对象和范围 |
| C05 | 聊天与表单共用草稿 | 修改同步；版本一致 |
| C06 | 完整对话、子页与右侧面板切换 | 单面板；关闭、返回与放大保持上下文 |
| C07 | 原操作结果、原对话与主通知同步 | 同一事件、不同视图，去重且不抢焦点 |
| C08 | 全局检索、资料关联与结果导出 | 分阶段补齐；不单列知识库入口 |

设置支持保持4组：S01个人资料与界面偏好；S02通知提醒偏好；S03连接、权限与数据管理；S04使用帮助与反馈。业务执行授权在原业务详情和生活／我的安排中管理，设置页只管理连接或通用偏好。

## 9. 验收场景与后续顺序

设计和实现时至少验证：

1. 一级入口恒定四个；每域4个二级页的全量规划，未建设页不展示；新增能力没有悄悄增添导航。
2. 子页首条发送只创建一条对话，全局与局部均可恢复；浏览和空输入不创建记录。
3. 从任一入口发送、重命名或恢复草稿，另一个入口看到同一状态；切换页面不造成回复串线。
4. 跨域对话可多处索引，全局不重复；解除单页关联不会删除其他地方的对话。
5. 主对话能直接回答；入口卡点击才导航；不强制拆对话。主对话历史可定位到相关讨论。
6. 同一收支事件重试只产生一次通知；待收、预留不冒充到账或扣款；后台通知不打断当前操作。
7. 聊天与表单共用草稿；只读解释保留确认，参数变更使旧确认失效；关闭面板不取消安排。
8. 定时付款可在账单找到原指令，在生活日历查看排期；订单、流水、安排与对话关联正确。

后续顺序：先讨论本稿 → 冻结对话关联、导航和面板契约 → 画主对话全局左栏、默认业务页范围左栏、切换二级页后的对话／确认等必要样图 → 用户认可样图后再实施 → 接回AA、定时、联动并验收。新前端仍须先看样图通过；本稿不替代该批准。
