2026-10-13续：用户已明确认可AA／定时业务样稿并授权“可以干吧”。本轮开始前端接入与页面验收，完成后开启AA／定时入口；商户工作流继续关闭。

## 1. 置顶与最近

- 固定主对话仍位于列表上方。普通对话分“置顶”和“最近”，替换“全部对话”；分区标题都是可点击的展开／折叠按钮，旁有方向箭头，支持键盘操作。
- 默认两个分区展开；无置顶时保留“置顶”标题，展开显示简短提示。折叠偏好按主页／二级scope保存于本机；刷新保持，不生成对话。
- 右键普通对话提供“置顶／取消置顶”和“重命名”。菜单动作不跳转对话；操作失败保留原状态并允许重试。主对话已有固定入口，不再置顶。
- 置顶是对话的全局属性；主页显示全部置顶，业务页只显示属于该scope的置顶。跨域同一对话取消置顶后所有视角同步，不复制会话。
- 置顶对话不在最近重复。置顶按置顶时间倒序、id稳定打破并列；最近沿用最近活动排序。置顶／取消不改对话活动时间。暂不加入拖动排序和归档。
- 常规标题不加气泡图标，长标题渐隐、侧栏可调宽、细渐隐滚动条继续保留。只有分区可折叠，不折叠底部四入口和个人菜单。

### 接口

现有摘要增加`pinned: bool`、`pinned_at: string|null`。增量表`chat_conversation_pins`以conversation_id为主键，不重建或清空旧表。

`PATCH /api/conversations/{id}/pin`，请求`{pinned: true|false}`（严格布尔），返回最新对话摘要。重复置顶保留原置顶时间；重复取消无副作用；未知id返回已有的不存在错误，主对话返回业务错误。

## 2. AA与定时后端

沿用[P3-B契约](contracts/fourth-batch-api.md)现有TasksService、资金预留与时钟，补齐DS工具和API整合。旧“任务中心三入口”的前端规划作废：AA／定时从“账单→收付款”进入域内详情与确认，不新增一级入口。

- AA：总额与参与者 → 消歧 → 均摊预览 → 确认创建请求 → 查看逐人状态 → 明确点击模拟付款 → 到账或取消。本人份额不计应收，发起不等于到账。
- 定时：金额、账户、收款人、含时区时间 → 预览 → 确认预留 → 后台到期执行 → 原对话／通知更新。应用重启按24小时窗口补执行；过期、取消释放未消费预留。
- 模型只能查询、创建和取消预览，不能确认、代参与者付款、推进演示时钟。相对日期先读取服务时钟，界面统一北京时间；模糊时段补问。
- 只读对话保留待确认；新草稿替换旧草稿。普通后续聊天不撤销已授权定时任务。结果区分确认受理、已安排、实际到账。
- AA／定时与跨场景联动独立开关；本轮不顺带开放商户工作流。生产主入口在AA／定时样稿与前端未验收前保持任务开关关闭，后端以隔离实例验收。
- 对话scope固定bills/payments；预留展示复用账户available_minor/reserved_minor。幂等失败重试复用原计划，任务事件按state_version防止状态回退。
- 表单联系人从`GET /api/tasks/recipients?query=`读取；为空列当前用户全部模拟联系人，非空按姓名、银行、尾号筛选。返回id/name/bank_name/account_hint，不由前端写死或在重名中猜选。

## 3. 样稿与实施分工

置顶：已有用户指定参考，直接按上述SPEC实现并浏览器验收。AA／定时只生成一张连贯评审板，包含AA明细、定时确认和已安排状态，复用目前已审配色与14.5px正文。用户通过前不实现这些新增运行页面。

后端agent负责AA／定时模型/API/事件整合及测试；medium前端agent只负责置顶／最近分组；主代理负责置顶存储、规格、图稿与集成。复用现有服务，不重写账本，不重复研究工具框架。

## 4. 本轮验收

1. 置顶、取消置顶、刷新和服务重启保持正确；主页与scope筛选一致，最近无重复记录，主对话不能置顶。
2. 两分区独立折叠，刷新保持；收起侧栏再展开仍正确；右键菜单和键盘可操作，无常驻铅笔。
3. AA舍入、部分到账、重复付款、取消后停止未付；必要的信息不足和同名补问。
4. 定时确认才预留、到期前不扣、到期仅一次、撤销／过期释放、服务重启恢复。
5. API／模拟模型测试优先，少量真实DS验证工具选择；任务开关关闭时原有五类业务不受影响。
