# 架构与技术决策

系统采用模块化单体：能力可以分别实现和替换，业务状态由统一账本和执行服务管理。研究算法通过适配器接入，不各自维护账户余额。

## 执行路径

中文消息 → 意图与参数 → 按需检索知识库或业务事实 → 必要追问 → 知识回答或步骤计划 → 简明预览与必要确认 → 业务提交 → 结果回执。

知识库解释产品、FAQ 和操作规则，余额与持仓直接查业务工具。主回答先给结论，依据可展开，用户继续办理时复用已知信息。

LangGraph 保存任务进度和对话状态。交易执行服务管理权限、确认、幂等与数据库事务。恢复一次图运行不代表获得执行权限，也不保证一次资金效果；这些条件在每次业务提交时检查。

## 分层

| 层 | 模块与职责 | 禁止承担的职责 |
|---|---|---|
| 交互 | 中文 Web 对话、追问、操作预览、确认、进度与回执 | 直接更新余额或授予权限 |
| 应用入口 | 可信会话身份、请求去重、API 契约、事件推送 | 接受模型声明的用户身份 |
| Agent | 识别需求、提出计划、选择只读工具、生成有证据的说明 | 签发确认凭据或直接写数据库 |
| 知识库与 RAG | 文档入库、章节分块、有效版本过滤、中文 BM25、DS 阅读与回答 | 不把知识文本当实时账户状态 |
| 模型适配器 | 云 API 差异、能力声明、超时、用量与错误规范化 | 因模型切换而更改已确认的经济参数 |
| 银行工具适配器 | 类型校验、身份上下文、授权与执行服务的统一入口 | 绕过最终执行检查 |
| 执行服务 | 确认验证、权限、余额、幂等、事务、资金预留与补偿 | 使用提示词作为资金校验 |
| 数据 | 账本、持仓、卡片、订阅、订单、事件与审计 | 用聊天历史代替业务事实 |
| 评测 | 固定任务、故障注入、期望状态和回放 | 靠模型说“已完成”判定交易成功 |

## 技术决策

| 决策 | 首版设计 | 理由与边界 | 状态 |
|---|---|---|---|
| ADR-001 服务组织 | Python 模块化单体 | 适合现有 Python 研究组件；降低多服务集成负担 | 首批已实现 |
| ADR-002 API 与类型 | FastAPI、Pydantic、OpenAPI、JSON Schema | 统一工具、服务和前端契约，生成客户端类型；业务约束仍单独校验 | 设计基线 |
| ADR-003 Agent 流程 | LangGraph 与持久化 checkpoint | 管理追问、确认和恢复；持久化不是交易授权 | 已实现图编排与 SQL 对话存储，节点 checkpoint/中断恢复后续补齐 |
| ADR-004 数据 | PostgreSQL、SQLAlchemy、Alembic | 使用与集成环境一致的事务语义；账本独立于 Agent checkpoint | PostgreSQL/SQLAlchemy 已运行，迁移工具后续补齐 |
| ADR-005 前端 | TypeScript、React、Vite | 展示实际任务与确认状态；不引入第二套业务规则 | 首批已实现并通过浏览器检查 |
| ADR-006 模型 | DS 官方 V4.1 Flash，`deepseek-flash` | 用户已确定，直连官方接口 | 真实 DS 首批用户流程已运行 |
| ADR-007 可观测性 | 结构化错误与关键操作记录 | 先满足排错和回执；完整 OpenTelemetry 按需要后置 | 精简基线 |
| ADR-008 内部转账 | 同一 PostgreSQL 事务完成借贷、费用、幂等及事件写入 | 不把本地内部转账拆为先扣后入的跨服务流程 | 设计基线 |
| ADR-009 外部联动 | 显式订单状态与补偿步骤 | 模拟商户失败时记录部分完成；不可逆步骤必须有明确处理 | 设计基线 |
| ADR-010 工具暴露 | 内部类型化工具，按需导出 MCP | MCP 是标准接口，不是授权机制；无必要时不另设网关 | 可扩展 |

| ADR-011 知识检索 | 中文分词、BM25、文档版本与分类过滤 | 不增加第二家模型服务，先建立可用检索 | 首版基线 |
| ADR-012 RAG 优化 | 按需要用 DS 改写查询或重排 | 由实际检索与回答问题驱动，不默认增加调用链 | 后续优化 |

这些技术选择针对当前项目。已安装的依赖由 Python/前端锁文件记录；表中未完成项属于后续设计，不将其视为已运行能力。实际范围见 [首批实施状态](10-首批实施状态.md)。

## 两个 wrapper 的契约

模型适配器提供 `propose_plan`、`extract_fields`、`summarize_facts`。每个响应附模型实际标识、配置版本、用量、耗时、错误类型与校验结果。工具调用上下文和供应商要求的字段由适配器维护，不写入普通用户日志。

上段为目标契约。当前适配器先提供统一 `complete(messages, tools, emit)`，负责官方请求、流式片段、工具参数与错误转换；独立提取/总结接口和完整用量记录尚未实现。

银行工具适配器提供只读查询、操作预览、受控提交、结果查询。只读数据也需检查归属。写工具的最终入口强制验证授权，调用者不能通过直接调用内部函数绕过检查。

原生工具调用、JSON 输出与服务端校验为基线。模型适配器直连 DS 官方，不为多供应商兼容添加网关。RAG 上下文通过独立检索接口加入，详情见知识库 SPEC。
