# 项目范围与原则

银小二 通过中文对话理解个人银行需求，规划步骤，并在模拟银行和模拟商户中完成操作。产品目标是六场景具备可验证的正常、异常和恢复路径。

## 可用性优先

先完成用户任务与知识库问答，再改善追问轮次、等待时间、改口和错误恢复。保留身份归属、必要确认、资金一致和基础数据隔离；复杂安全体系与大规模研究评测后置。

## 官方要求与内部选择

官方赛题为银行 AI 智能体，至少覆盖三个场景，鼓励全部覆盖；国内评分为任务完成率 40%、安全合规性 30%、创新性及交互体验 30%。来源：[官方赛题](https://fintechathon.g-ican.com/#/)、[官方规则](https://fintechathon.g-ican.com/#/rule)，本会话于 2026-10-10 核对。

项目选择完整设计六场景。内部使用 HTTP 接口和自动化评测支持研发，这是工程选择，不宣称为官方指定协议。首版交互以中文 Web 对话、操作预览、确认卡片、回执和任务进度为设计基线；APP 或 IM 渠道通过适配接口扩展，最终渠道覆盖需对照官方说明核实。

## 六场景需求

| 编号 | 场景 | 完成边界 | 验收关注点 |
|---|---|---|---|
| SC-01 | 智能转账 | 收款人检索、消歧、即时与定时转账、AA 收款请求 | 确认绑定、正确入账、定时授权、重试不重复扣款 |
| SC-02 | 账单分析 | 分类、异常提示、月报和年报 | 数据覆盖、精确汇总、结论可追溯、异常误报 |
| SC-03 | 理财操作 | 模拟产品比较、风险匹配、申购与赎回 | 适当性规则、费用与限制披露、持仓和现金一致 |
| SC-04 | 卡片管理 | 模拟申请、调额、限制或解锁、挂失 | 合法状态迁移、账户归属、敏感动作确认 |
| SC-05 | 订阅与代扣 | 周期识别、续费提醒、商户取消和代扣撤销 | 候选与已确认订阅分开，取消能力与真实结果核验 |
| SC-06 | 跨场景联动 | 需求拆解、预算预留、定时触发、模拟商户订单 | 总预算、取消条件、部分失败、补偿与实际回执 |

## 完成标准

“尽善尽美”落实为明确验收，而非无边界增加功能。每个场景必须有正常路径、信息不足路径、拒绝或越权路径、工具失败路径，以及最终状态检查。六场景的完成状态分别记录，未通过的场景保留未通过状态。

金额、时间、用户身份、收款人和产品必须来源可追溯。模型提供计划建议；服务端独立决定是否允许执行。系统不得把工具失败包装成成功。

## 项目原则

1. 所有资金、卡片、理财和商户操作均发生在模拟环境。
2. 身份与权限来自可信服务端上下文，不能由模型文本或请求中的用户 ID 授予。
3. 对写操作提供清晰预览与有效确认；参数变化需要重新授权。
4. 金额使用整数最小货币单位，首版账本使用人民币分；模型不得自行进行账务提交。
5. 每个模块有独立输入输出、失败语义、来源和验收案例。
6. 已有机制如实引用；自己的创新用同模型、同任务的对照实验说明。
7. 保留版本、关键失败和实际结果所需的最小记录，不把模拟环境结果称为真实银行验证。
8. 知识库由工程侧构建，用户不用逐项决定检索算法。主模型固定 DeepSeek 官方 V4.1 Flash。

## 交付边界

报名截止 2026-11-01，作品提交截止 2026-11-02，日期按中国标准时间。必交技术文档、答辩材料、源码与部署材料、安全自评报告；演示视频可选。具体格式与容量以报名页面为准。

当前不接入真实银行、真实付款、真实商户下单，不进行云资源开通或对外部署。国产云端仅指模型推理的选择，应用托管方式另行决定。
