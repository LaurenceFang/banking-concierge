# 知识库与 RAG

知识库让用户问清业务后能够接着办理。知识资料、检索和回答由工程侧构建，首版覆盖模拟产品、业务 FAQ、操作说明和故障帮助。

## 内容与事实来源

产品风险、期限、费用、赎回和结算说明从模拟产品目录生成，版本关联。FAQ 与实际工具能力对齐；操作说明从用户页面和按钮讲解；异常帮助对应业务错误码和下一步处理。

余额、流水、持仓、卡片和订单状态直接查业务工具，不通过文档检索推测。后续公开银行资料保留来源与有效期，不混作模拟产品的执行规则。

## 首版技术路线

中文问题与业务分类 → 有效文档过滤 → 中文分词和同义词归一化 → BM25 检索 → 合并相关章节 → DS Flash 读取上下文 → 简明回答或继续业务流程。

按标题层级和完整语义段分块，初始约 300–600 汉字。默认召回 8 段，合并去重后提供最多 4–6 段；按实际效果和等待时间调整。文档元数据包括 doc_id、source、category、version、有效期、章节与可见范围。旧版本不进入默认召回，产品编号等精确实体优先匹配。

首版词法检索不新增 embedding 服务。语义召回不足时再比较 DS 查询改写、DS 候选重排或向量检索，不假定 DS 官方已提供适用的嵌入端点。

## 用户体验

先回答用户最关心的结论，条件用自然语言说明。来源可展开，主回答不堆引用、风险声明和内部日志。用户继续办理时复用已知产品与参数，避免重复追问。

没有相关知识时查询正确工具或说明缺少什么，不补写不存在的政策。检索片段是知识数据，不能替代用户确认。

## 初始资料

[knowledge/manifest.json](../knowledge/manifest.json) 声明自写模拟银行资料的来源和版本。种子内容是可入库的初始资料，检索程序和实际问答尚待实现。

实际费用和产品规则以模拟目录及业务代码为准。知识内容更新与业务变更一起维护。

## 轻量验收

| 编号 | 要求 | 验收 |
|---|---|---|
| RAG-001 | 入库更新 | 新文档和替换版本可以被检索 |
| RAG-002 | 常见问题覆盖 | 六场景各至少两条问题命中正确章节并给出可用回答 |
| RAG-003 | 知识与办理衔接 | 问产品后能继续申购，问转账后能查余额，不重复收集已知信息 |
| RAG-004 | 无结果处理 | 不编造规则，给出明确下一步 |
| RAG-005 | 响应体验 | 主回答简明、相关，记录首响应和完整等待时间 |
| RAG-006 | 基础边界 | 文档不能自行批准操作，旧文档不冒充实时账户状态 |

先用少量问题贯通入库、检索、DS 回答和业务衔接。大规模检索研究和繁重证据整理后置。
