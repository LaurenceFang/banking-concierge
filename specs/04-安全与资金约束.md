# 必要安全与资金约束

首版安全服务于可用的银行操作。保留身份归属、明确确认、余额与账务一致、重复提交防护和基础不可信数据隔离；复杂安全研究不进入主线排期。

## 首版必须具备

| 编号 | 行为 |
|---|---|
| SEC-001 | 查询和操作只作用于当前可信身份有权限的账户 |
| SEC-002 | 资金、卡片敏感变更和取消操作有清晰预览与用户确认 |
| SEC-003 | 确认对应当前金额、对象和计划；用户改口后更新预览 |
| SEC-004 | 文档、备注和工具结果不能替用户批准操作 |
| FIN-001 | 金额使用整数分，余额、持仓、费用与流水一致 |
| FIN-002 | 并发和资金预留不突破可用余额 |
| FIN-003 | 重复点击和重试不产生第二次经济效果 |
| FIN-004 | 内部转账在同一事务中提交，失败不留下部分扣款 |
| FIN-005 | 超时先查原结果，未完成不报告成功 |

首版用服务端身份、计划版本和确认记录实现这些约束。无需先建立签名授权平台、复杂能力令牌或完整策略治理系统。

## 简明用户交互

必要条件集中展示和确认，普通只读查询直接处理。不重复确认已确认且未改变的参数；失败给出明确原因和恢复入口。

## 后续研究与比赛材料

四类攻击各保留少量代表案例，满足基础检查和安全自评。CaMeL 等复杂隔离、扩大红队、独立回放与完整审计链在用户主路径稳定后按需要开展。材料如实记录已实现措施和已知问题，不扩展为额外研发门槛。

## 秘密与数据

API 密钥使用环境变量或本机加密凭据，不进入代码和普通日志。知识问答引用业务事实，上传资料作为数据处理。全部银行与商户动作仍在模拟环境。
