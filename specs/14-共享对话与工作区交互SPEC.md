# 共享对话与四入口工作区交互 SPEC

日期：2026-10-13。状态：用户已认可v2样稿，核心工作区已实现并验收；逐项范围见[实施状态](15-四入口工作区实施状态.md)。上位规划：[四入口功能地图](13-产品功能地图与四入口规划.md)，增量接口见[工作区契约](contracts/workspace-v2-api.md)。本SPEC仍包含后续能力，不以整份规格充当完成声明。

修订v2：一级入口直接打开第一个已实现二级页并展开左栏，不增加目录选择页、不先隐藏再弹出。主页左栏列全部普通对话；业务页左栏只列当前二级范围相关对话。正文移除相关对话区域，沿用同一条消息记录。银小二旁主页图标回到全局主对话。v1样稿的正文历史区域已被本修订替代。

## 1. 首次交付范围

先贯通“主对话 → 账单／收支明细 → 切换收付款 → 左栏相关对话 → 同一对话侧面板 → 转账确认 → 原对话与主通知”。四入口共用导航；其他现有业务后续迁入同一结构。借贷等远期页不作为首轮实现，也不做空页面。

沿用已有灰绿配色、正文文楷 Regular、标签新晰黑 Regular。左栏可收起；四项业务入口固定2×2，桌面不增加第二层竖向侧栏。二级导航位于业务内容顶部。完整对话、业务页面都使用同一个中央工作区。

## 2. 唯一状态与关联

| 概念 | 拟定最小数据 | 不变量 |
|---|---|---|
| 对话 | id、kind(main/conversation)、title、updated_at、read_cursor、status | 所有展示位置引用同一id与消息集合；左侧普通列表不重复收录主对话 |
| 业务范围 | domain、section | domain固定accounts/bills/wealth/life；section使用稳定键，不以中文标题作主键 |
| 对话关联 | conversation_id、scope、object_ref可空、primary、source、user_override | 同一范围和对象不重复；手动移除后不立即被自动归类重新加入 |
| 页面位置 | route、object_ref、filters、return_location | 菜单浏览只记录返回点，不继承无关业务授权或事项 |
| 工作区 | center(chat/page)、active_conversation_id、panel、sidebar_collapsed | 中央可见对话与右侧对话不会同时显示同一消息流 |
| 左栏范围 | sidebar_scope(global或domain/section)、scope_request_id | 由当前工作区路由确定；迟到的旧范围列表响应不得覆盖新范围 |
| 右面板 | closed/chat/detail/confirm、target_id、return_panel | 同时只有一个；确认结束可回原对话 |
| 草稿 | id、operation_type、parameters、version、conversation_id可空、task_id可空 | 聊天与表单共用；一个对话可有多个草稿，但确认明确绑定某个草稿版本 |
| 消息与事件 | message_id、conversation_id、client_request_id、event_id可空 | 重试不重复创建消息、对话或结果通知 |

这些是拟定契约字段，不声称当前API已提供。实现前依据现有ConversationStore与Agent接口写兼容增量，避免重建历史。四个入口是视图组织，不对应四个Agent。

## 3. 导航和恢复

- 默认进入主对话；主对话可直接查询、讨论和办理。输入区使用“有什么想问，或想让我帮你办的事？”等自然提示，不把“万能”当能力承诺。
- 主对话回答可附结构化导航链接。链接使用受支持的内部路由与对象引用；模型生成的任意字符串不直接作为页面路由。用户点击才跳转。
- 一级入口直接进入第一个已实现子页并展开左栏，账单进入收支明细；顶部二级页签可以切到第二、第三页。不增加一级选择页面，不先收起再展开造成闪动。v2样稿B展示默认收支明细，C/D展示切到收付款。
- 一级默认页保持既定方向：账户资金总览、账单收支明细、财富持仓与计划、生活我的安排；二级显示顺序把默认页放在第一位。未实现页不展示。
- 主页面左侧点普通对话：中央显示完整聊天，左栏保持全局列表。业务页面左侧点对话：中央保留业务页，右侧打开该对话。侧面板“放大”切到中央聊天，但保留业务scope及返回点；放大不等于回主页。
- 左栏顶部固定“主对话”；点击它或银小二旁主页图标均返回主页面，中央为主对话、左栏恢复全部普通对话。底部四入口和个人菜单不随范围变化。
- 切换二级页立即切换左栏范围；关闭旧页右面板但保留对话输入与草稿，新页不自动选中第一条历史。首次进入无历史时显示简短空状态，仍可从左栏新建。加载中不展示上一页的历史冒充当前页。
- 换页、收起侧栏、关闭右面板均保留输入和草稿；不等于撤销、取消或重开对话。浏览器前进后退恢复位置，不重发消息或操作。
- 草稿输入按conversation_id保存；未创建对话按本地compose_id保存。切换期间仍生成中的回复写回原conversation_id，新对话不会收到旧回复。
- 刷新后以服务端对话与草稿为准。未发送的文字可在本机恢复；不能把仅保存在本机的文字显示成已发送。对象不存在或无访问权限时展示可恢复错误和返回入口。

## 4. 新建、继续与两处历史

### 新建

点击左栏“新建对话”只开启编辑态；在主页不预设业务分类，在业务页带当前二级范围。首条发送时，以一个幂等请求创建普通对话、保存首条消息及显式页面范围。成功后返回唯一id，更新全局与当前范围索引；正文不再设独立历史或发起对话模块。网络不明时重试同一client_request_id，不能创建两条同名对话。

创建已成功但模型回答失败：对话和用户消息仍保留，显示“重试回复”；重试不复制用户消息。创建本身失败：保留编辑内容，显示未发送，不伪造持久历史。

### 继续

点击任何历史入口都加载原id。页面从某条对话跳转而来时，可“继续原对话”；手动菜单进入时不自动把新讨论挂到最近生日安排上。新对话与继续已有对话的按钮文案清楚区分，不每次弹窗追问。

### 分类与检索

- 子页发起自动关联该scope；对象详情发起同时关联object_ref。只传当前选中对象和必要筛选，不传全站数据。
- 全局发起可先无分类；明确主题或实际业务对象形成后再关联。不是出现关键词就归类。
- 跨域对话可有多个scope，只有一个主分类；主页全局列表去重，业务页左栏按当前二级scope筛选。排序采用对话最近活动时间，分页稳定。对象详情的选中对象用于新讨论上下文，本轮不静默进一步缩窄左栏列表，避免二级范围不稳定。
- 用户修改标题，两处同步；任一处阅读更新同一read_cursor。仅页面可见不算读过尚未展示的消息。
- “移出本页”只删除关联；归档作用于整条对话，所有默认列表同步隐藏，可从归档恢复。全局删除不是本轮新增需求。
- 主对话中的相关片段用消息定位链接表示，不把整条主对话复制到所有子页。打开定位链接只导航，不重新提问。

## 5. 面板转换规则

| 当前状态 | 触发 | 下一状态 | 保留内容 |
|---|---|---|---|
| 完整对话／右侧关闭 | 点业务入口链接 | 业务页／右侧关闭 | 来源对话与返回位置 |
| 业务页／右侧关闭 | 左栏打开相关对话或新建 | 业务页／chat | 页面位置、范围和筛选 |
| 任意工作区 | 点击一级业务入口 | 默认二级业务页／closed，左栏展开并按范围筛选 | 原对话、输入与草稿 |
| 业务页 | 切换顶部二级页签 | 目标业务页／closed，左栏更新为目标范围 | 旧页对话与草稿，不自动恢复旧面板 |
| 任意业务工作区 | 点击主页图标或固定主对话 | 主对话／closed，左栏展开且显示全部对话 | 业务草稿与可返回位置 |
| 业务页／chat | 放大 | 完整对话／右侧关闭 | 原业务页返回位置 |
| 业务页／chat | 打开对象详情 | 业务页／detail | 原对话面板返回点 |
| chat或closed | 当前对话生成新待确认动作 | 原中央视图／confirm | 原面板及草稿版本 |
| confirm | 返回对话 | 原中央视图／chat或closed | 未执行的草稿与确认版本 |
| confirm | 返回修改 | 草稿编辑视图 | 原参数；保存实质变更后产生新版本 |
| confirm | 确认成功 | 原对话显示结果，可返回chat | 原操作id、结果与对象链接 |
| 任意面板 | 关闭X或Escape | closed | 对话、草稿、执行状态 |

仅当前可见对话的新确认版本可自动展开；后台其他对话的动作只标待处理，不夺取当前面板。记录dismissed(draft_id,version)，同版本不反复弹出；用户可主动点“核对”恢复。

一条对话有多个待确认动作时，消息明确各动作，点击哪个确认哪个；不得只按“当前最后一笔”隐式提交。确认期间切换页面，结果仍落回原操作。

桌面有足够宽度时使用左栏、中央、单右面板；空间不足时面板覆盖工作区或全屏。手机复用同一状态机，支持返回和关闭；不把三栏缩成细条。实现时检查键盘焦点、关闭后焦点恢复、按钮可读标签。

## 6. 草稿与执行

聊天提议或表单填写只写草稿。金额、收款人、付款账户、时间等办理参数变更才增加version，使旧确认失效；询问手续费或解释状态不改变版本。前后端共同核对版本，并在冲突时显示最新参数供用户重新核对。

确认按钮提交draft_id、version及幂等键；重复点击或重试返回同一操作结果。请求结果未知时显示“正在核对结果”，通过原操作查询恢复，不立即发起新转账。业务拒绝则显示原因并保留可修改草稿。

主对话收到办理需求仍可直接办理，不强制另开普通对话。由纯表单创建的操作可以没有聊天记录；用户随后发起讨论时关联原对象，而不是重做一次操作。

## 7. 收支与结果通知

使用已确认的业务事件更新页面、原对话和主对话通知。每个event_id在每个目标视图至多投递一次；向主对话本身办理的操作返回结果时，不再追加同一条主通知。网络重连补发依游标去重。

到账、扣款、预留、待收、退款处理中必须分别标记。通知附对象链接与原对话链接；普通通知不打开面板、不更换中央页面。模型不负责推算一笔事件是否真实发生。后续可汇总低优先级通知，首轮先做明确单条与去重。

## 8. 验收用例

| 编号 | 操作 | 预期 |
|---|---|---|
| UX01 | 进入账单、浏览、打开空聊天再关闭 | 新对话数量不变 |
| UX02 | 收付款范围左栏新建并首条发送，模拟超时后重试 | 局部左栏出现一次，回主页全局列表仍是同一id，用户消息只有一条 |
| UX03 | 业务页左栏继续历史，回主页打开同名对话 | 消息、标题和草稿一致，无额外模型请求 |
| UX04 | 发送后立即切换到另一条对话 | 回复写回原对话，新对话保持原内容 |
| UX05 | 重命名、阅读、归档、恢复 | 所有入口同步；归档可恢复 |
| UX06 | 跨域关联后移出一个子页 | 其余索引和全局记录保留，自动分类不立即反悔 |
| UX07 | 主对话查收支，回答附链接 | 不强制新建或跳页；点击才导航，可返回原位置 |
| UX08 | 主对话相关片段从业务页打开 | 定位原消息，不复制会话、不重问 |
| UX09 | chat→confirm→返回对话→关闭→手动打开 | 同一草稿；同版本关闭后不自行反复弹出 |
| UX10 | 待确认时问解释，再修改金额 | 解释不失效；金额变化后旧版本不能提交 |
| UX11 | 确认重复点击、响应中断后恢复 | 同一操作只执行一次；未知结果可按原id查回 |
| UX12 | 同一到账事件重复投递 | 主通知仅一条；页面更新但不抢焦点 |
| UX13 | AA待收或创建预留 | 不能生成已到账或已扣款通知 |
| UX14 | 在无关对话中收到另一对话的确认事件 | 仅更新待处理标记，不覆盖当前面板 |
| UX15 | 窄屏、键盘操作与刷新恢复 | 信息完整可读；能返回、关闭和继续原草稿 |
| UX16 | 从主页点账单 | 直接打开第一个二级页收支明细，左栏展开，只列该范围历史，无中间目录页与正文相关对话区 |
| UX17 | 从收支明细切到收付款，旧列表响应延迟返回 | 只显示收付款历史，旧响应不覆盖；草稿保留，右面板不串线 |
| UX18 | 点击银小二旁主页图标或固定主对话 | 回主对话并恢复全部普通对话，底部四入口与个人菜单位置保持 |

以上是待实现验收规格，不是本轮测试通过报告。

## 9. 节省额度的实施分工

### 侧栏细化与下一轮置顶（2026-10-13补充）

本次按用户提供的Codex截图调整：桌面侧栏可拖动，最小200px、最大600px，且给正文至少保留480px；宽度本机记忆，手机仍用固定侧栏。标题不足宽时末尾渐隐，不显示省略号；完整标题保留悬停提示。重命名仅在对话的右键菜单出现，支持Shift+F10与Escape，不常驻铅笔。对话列表与四入口的区块间隔由13px增加到约17px，入口区顶部留白由15px增至20px，合计视觉间隔增加约三分之一。侧栏和主对话滚动条变细，轨道透明，滑块使用接近背景的灰绿。

**下一次工作必须加入“置顶”分区，本次不实现。** 后续SPEC需明确置顶／取消置顶、分区排序、主页与二级范围的显示关系、刷新持久化；从对话右键菜单提供操作。不得在本轮展示不可用的置顶按钮或假分区。

本轮由主代理完成SPEC和单次四状态出图，不再让多个Agent重复研究或各画风格。视觉修改优先聚焦已指出的一处；不预生成16个子页。

样稿通过后才启动两个实现subagent：共享对话与关联数据、前端工作区（遵循用户指定medium）。主代理负责契约审查、合并和一条完整用户路径。先用确定性数据测导航和状态，再用少量真实DS调用验证理解与办理；不用模型反复测试普通按钮。

本轮纵向流程及已有账户、财富、生活页面已迁入；AA、定时及联动基于已有暂停代码审查后接回。本地实现和验收不等于公网部署。
