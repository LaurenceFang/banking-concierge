# 主会话、临时事项和按需办理面板

2026-10-12 用户审稿后暂定第四轮界面作为基线；少量层次和强调色在真实页面里微调。关联 M07、M11、M14 和共享会话/前端设施。本批不宣称完成 LangGraph 节点 checkpoint 或全部六场景。

| 需求 | 用户行为与结果 | 验收 |
|---|---|---|
| UI-001 | 主会话日常助手常驻，显示模拟银行/订阅真实事件回执 | 重复确认或刷新不重复生成通知 |
| UI-002 | 每项临时需求是独立会话，可新建、切换、改名、恢复 | 刷新可见原消息、来源和操作；上下文不混入另一事项 |
| UI-003 | 左侧会话栏可收起，收起后仍可展开 | 电脑及手机均可发现入口，无滚动/遮挡陷阱 |
| UI-004 | 新待确认动作自动打开右侧面板，无动作时隐藏 | 转账/订阅动作呈现同一工作区；讨论送花不产生假订单 |
| UI-005 | 手动关闭后不反复弹出，同一动作可从聊天重开 | 按会话与动作ID记录状态，切换不确认其他事项 |
| UI-006 | 完成/取消在会话保留回执，主会话汇总完成通知 | 页面与服务端状态一致，失败不显示成功 |
| UI-007 | 使用真实中文字体文件、轻字重和柔和灰白层次 | 原生桌面、手机渲染比较；知识来源正常展开 |

正式 HTTP 与数据结构见 [第二批契约](../contracts/second-batch-api.md)。支付宝通知只作早期图稿示意，本批主会话接模拟银行和模拟订阅事件；实际商户接入待后续规格。
