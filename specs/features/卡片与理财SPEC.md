# 卡片与理财规格

关联 SC-03、SC-04，模块 M19、M20 和通用规划、安全与账本模块。全部产品与审批在模拟环境中定义。

## 卡片

| 编号 | 行为 | 验收重点 |
|---|---|---|
| CARD-001 | 申请 | 生成可追踪申请记录；提交申请不等于已获批 |
| CARD-002 | 调整额度 | 可信身份、确认和模拟审批规则；越限不得写入 |
| CARD-003 | 限制与解锁 | 区分 ACTIVE、FROZEN、LOST、CLOSED 状态；合法迁移可检查 |
| CARD-004 | 挂失 | 明确后果后确认；操作成功与卡片状态一致 |
| CARD-005 | 状态冲突 | 已关闭或已挂失卡片不通过普通解锁恢复 |
| CARD-006 | 重复操作 | 同键不产生第二申请或重复状态事件 |

参考当前 τ² banking_knowledge 工具的状态模式，补充归属、授权和本项目的风险规则。当前状态说明与执行语义一致，不把工具返回文本当状态事实。

## 理财

| 编号 | 行为 | 验收重点 |
|---|---|---|
| WEALTH-001 | 模拟产品比较 | 产品、费用、期限、风险、流动性来自产品目录，附来源版本 |
| WEALTH-002 | 风险档案 | 必填信息不足时追问，未经评估不能默认风险等级 |
| WEALTH-003 | 适当性校验 | 超过允许风险等级的申购拒绝，并解释对应规则 |
| WEALTH-004 | 申购 | 确认绑定产品、金额、费用和限制；现金与持仓按明确结算状态更新 |
| WEALTH-005 | 赎回 | 区分申请、受理、结算和到账；锁定期及费用规则生效 |
| WEALTH-006 | 并发与恢复 | 余额、持仓、幂等及确认约束在提交时检查 |

申购和赎回的结算时钟由合成环境控制；不能把待结算视为已到账。产品规则由确定性代码计算，语言模型负责解释和提议，不预测保证收益。

IndicBankBench 提供产品与拒绝场景参考；本题完整风险匹配、持仓和结算逻辑需要自研。具体阈值和产品条款先由模拟目录固定，不编造真实银行政策。
