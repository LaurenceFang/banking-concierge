# 定时与跨场景联动规格

关联 SC-06、SC-01、SC-05，模块 M21 和通用执行模块。首个任务为预算受限的生日服务安排，鲜花与蛋糕使用模拟商户。

## 用户路径

理解日期、对象和预算 → 查询可用资金与服务 → 提出含依赖的计划 → 展示每项费用与取消规则 → 用户确认具体范围 → 资金预留 → 定时或即时调用模拟商户 → 核验订单与账务 → 展示实际结果。

用户可以撤销尚未执行的授权。执行中的取消依据订单状态和条款处理，不承诺不可逆动作能够完整回滚。

## 需求与验收

| 编号 | 行为 | 验收重点 |
|---|---|---|
| CROSS-001 | 预算约束 | 订单、手续费和预留总额不得超出已确认预算 |
| CROSS-002 | 资金预留 | 预留降低可用余额；拒绝、过期或取消时按状态释放 |
| CROSS-003 | 步骤依赖 | 未完成前置查询或授权时不下单 |
| CROSS-004 | 定时执行 | 固定时钟、触发窗口、单次效果、授权失效与撤销可测试 |
| CROSS-005 | 部分失败 | 一家商户成功另一家失败，准确报告部分完成，执行定义的补偿 |
| CROSS-006 | 补偿失败 | 保留待处理状态及资金归属，不报告已全部退款 |
| CROSS-007 | 状态变化 | 恢复前核实预算、账户与商户条件，条件变化后重新计划 |
| CROSS-008 | 不可信商户内容 | 商户消息中的附加付款指令不能超出确认范围 |
| CROSS-009 | 最终核验 | 下单响应、订单持久状态与资金结果一致才计完成 |

## 商户与订单契约

商户适配器固定报价、下单、查询、取消与退款能力。明确 `PENDING`、`CONFIRMED`、`CANCELLED`、`FULFILLED`、`FAILED`、`REFUND_PENDING`、`REFUNDED` 状态与合法迁移。报价失效或参数变化需更新计划，不由模型猜测替代商户条款。

故障 fixtures 包括报价过期、库存不足、响应丢失、重复下单、订单已经履约和退款失败。使用可复现时钟，不依赖真正等待生日日期。

AppWorld 提供多应用状态验收方法，Temporal 提供持久执行与补偿参考；首版在统一应用架构中实现模拟商户和业务状态。多步组合属于工程能力，自研规划策略的贡献通过对照评测单独说明。
