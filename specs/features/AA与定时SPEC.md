# AA收款与定时转账

2026-10-13，关联TRANSFER-010/011、M21。具体字段和示例规则见 [P3-B契约](../contracts/fourth-batch-api.md)。

AA路径：用户给总额、参与者及收款账户 → 同名消歧 → 精确到分的均摊预览 → 确认创建请求 → 展示每人待付/已付 → 明确模拟对方付款后核对银行入账。创建请求不冒充到账；我方份额不变成应收。取消保留已收款，只停止未付部分。

定时路径：明确账户、收款人、金额和带时区时间 → 展示预留、时间与24小时执行窗口 → 确认预留 → 到期后台执行并核对账本 → 原事项与日常助手收到结果。执行前可撤销并释放预留；重启补执行须仍在授权窗口内。

| 编号 | 验收 |
|---|---|
| AA-001 | 100分三人分摊总和等于100分，余数分配稳定 |
| AA-002 | 新请求不写账务；部分到账只记对应参与者 |
| AA-003 | 重复模拟付款只产生一笔效果，余额不足无假到账 |
| AA-004 | 取消后已收款保留、待付款停止，不能再付款 |
| TIME-001 | 到期前不执行，预留降低可用余额但不降低账面余额 |
| TIME-002 | 重复worker、服务重启只执行一次，双方流水平衡 |
| TIME-003 | 撤销、过期、失败正确释放预留；后续聊天不偷偷撤销已授权任务 |
| TIME-004 | 模糊或无时区时间不得静默执行；确认单显示北京时间 |
| TIME-005 | 转账/理财不能消费已预留资金，跨模块并发校验 |

当前是本地模拟运行；后台依赖应用进程存活，停止应用不等于任务失效，重启按执行窗口恢复。模拟付款不触达真实联系人，模型没有代他人付款或确认按钮权限。
