# 银小二 工程规格

本规格包定义六场景银行 AI 智能体的范围、接口、状态变化、安全约束和验收方式。开发按规格逐项实现，使用相同接口比较已有基线和改进方法。

版本：0.6；日期：2026-10-12；状态：第二批 P2 账单/订阅及会话界面已集成并完成本地验收。六场景总体规格继续按阶段推进，已有结果见 [首批状态](10-首批实施状态.md)和[第二批状态](11-第二批实施状态.md)，本批接口见 [第二批契约](contracts/second-batch-api.md)。

## 已确定的方向

- 六个官方场景全部进入产品范围，按依赖顺序实现和验收。
- 主模型使用 DeepSeek 官方 V4.1 Flash，API 模型 ID 为 `deepseek-flash`；本地推理不进入首版范围。
- 可用性、六场景完整流程和知识库优先；安全保留必要业务约束，研究级防护与繁重证据整理后置。
- 代码按能力细分，以模块化单体组织，统一账本、身份和执行权限。
- 维护者负责需求取舍，贡献者按规格实现，使用者按完整用户路径验收。
- 复用组件需要明确来源、许可和边界；创新以固定基线上的对照实验验证。
- 当前实现包含模拟转账、账单统计与导入、订阅检测和操作、会话与通知、知识库检索及 DS 编排；完整六场景应用尚待实现。

## 规格与证据的关系

功能保留简明需求、验收案例和实际结果，优先让用户完整办成事情。关键失败记录足以支持修复，不为每轮开发制作大型证据包。接口连通与完整业务验收分别说明。

范围和工程决策以本规格包为准；官方规则以官网最新通知为准。项目自建 HTTP 接口和内部评测，不将其宣称为官方指定协议。

## 后续需要补齐

- 当前余额、流水、转账、账单、订阅与 RAG 已通过实际 DS 和浏览器检查；理财、卡片和跨场景任务随实现逐项检查。
- 开发依赖由 `uv.lock` 和 `web/package-lock.json` 锁定，当前运行 PostgreSQL 17。
- 官方是否提供沙箱、数据集或专门评测协议，以及决赛任务形式。
- 按已实现功能更新进度和内部目标日期。

开放项按所属功能处理，版本进度以可运行用户流程为准。
