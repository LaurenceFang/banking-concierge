## 可用功能

| 功能 | 当前行为 | 必要区分 |
|---|---|---|
| 卡片 | 两张模拟卡，查状态/额度，冻结、解锁、挂失、日限额/信用额度调整 | 冻结卡片不冻结整个存款账户，挂失/关闭不能普通解锁 |
| 申请 | 独立确认后保存申请和回执 | 待审核不等于批准或发卡 |
| 风险评估 | 用户主动回答五项，规则计算R1–R5与适配限制 | 不从闲聊推测答案，不是训练出的评级模型 |
| 产品比较 | 三个自写模拟产品，风险、起购、费用、锁定期和业务日T+1 | 不提供真实银行产品或保证收益 |
| 申购 | 预览不扣钱，确认原子扣本金/费用并受理订单，到期入持仓 | 待结算不计已持仓 |
| 赎回 | 确认预占份额，到期才按净额入银行账户 | 待结算不算现金到账，锁定期和可用份额在提交时复查 |
| 恢复 | 订单、持仓、模拟日期、确认单和两阶段通知持久化 | 重复确认/结算不二次扣款；同订单结算回执不退回旧受理状态 |
| 账单联动 | 投资本金投射为转账，手续费单独计金融服务消费 | 不把申购本金计消费、赎回本金计收入 |

主应用已显式启用P3工具和抽屉；工厂函数保留默认旧模式，支持隔离回归。风险评估从理财表单完成，聊天负责查产品/状态、说明规则与创建预览，不能代填档案、批准动作或推进模拟日期。

- 后端全套 **116 项通过，无跳过**；包含专用 PostgreSQL 测试库的14项转账、订阅、卡片及理财检查。对外观测库未重置。Ruff通过。

- SQLite/API覆盖无风险档案、风险不匹配、锁定期、额度和卡片版本冲突、其他会话确认拒绝、申请不发卡、资金/持仓竞争、事务回滚、手续费、到期恢复、重复结算、旧事件晚到与模型在途保存。
- 专用 PostgreSQL URL限定 `127.0.0.1:55432/concierge_test`。bank专项重建自己的银行测试表；新理财夹具不drop银行表，只恢复其测试账户并清理自己的新增资金分录。各包测试串行执行。
- **真实 DeepSeek隔离API**：冻结卡片预览和确认；申购1000元灵活资金，T+1结算；赎回1000元，再T+1到账，用户现金恢复原值。使用独立SQLite库、明确合成风险答案。
- **真实主运行页面**：DS聊天生成1000元申购确认单，页面确认并核对待结算无持仓；体验下一业务日后持仓入账；DS为实际持仓生成赎回单，确认后可用份额为0、现金未提前到账；下一业务日结算后现金恢复。主库日常账户最终为9,050,444分，银行流水16笔，两笔理财订单均已结算，模拟业务日2026-10-14。该数值是本轮快照，不是种子常量。
- CUA Chrome **1440×1024桌面、390×844手机**：卡片冻结/申请预览与取消，五项无默认答案/缺项禁用，R3与R5不适配，错误小数拒绝，真实预览、关闭/重开/刷新/会话恢复、非空持仓及赎回取消。原账单和订阅回归可用。

模拟净值固定为1元，无收益预测或市值变化。本地保留合成风险档案、已完成示例订单及验收会话；私人凭据和运行数据库不进入仓库。
