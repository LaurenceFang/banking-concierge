# 六场景整体联调 SPEC

日期：2026-10-15。用户授权先写规格再联调，现有界面不改；节省模型调用，不做 hash 检验、dry-run 或大型证据包。

## 范围与通过条件

使用现有应用、模拟银行与商户，在隔离验收数据库实际执行业务。六场景为转账、账单、订阅、卡片、理财、跨场景安排；AA与定时作为转账及跨场景的补充路径。

| 路径 | 通过条件 |
|---|---|
| 同一对话切换六场景 | 查询不误执行；新办理要求替换旧待确认单；已确认订单不被新聊天撤销；回执对应原事项 |
| 转账→账单 | 确认后余额与流水一致；重复确认不重复扣款；查询能看见刚完成的支出 |
| 订阅与卡片 | 取消合同与停代扣含义准确；卡状态改变可查询；不同对话的待确认单互不串用 |
| 理财 | 必要档案完整；受理与结算分开；申购/赎回后的现金、持仓、订单一致 |
| 跨场景安排 | 按已确认预算执行；部分失败停止后续订单；退款未到账不减少净支出，到账后回执更新 |
| AA与定时 | AA已收与未收分开；定时预留、撤销和到期结果准确 |
| 异常恢复 | 余额不足无扣款；取消不执行；刷新/重启保留事实；模型失败重试不复制已生成动作 |

## 实施顺序与额度

1. 复用现有自动测试，先跑一轮基线；仅对发现的问题补针对性测试。
2. 增加一条同一应用、同一对话跨场景的集成检查，实际提交模拟确认并核对状态；重启使用原数据库。
3. 少量真实DS多轮请求验证工具编排与只读追问；先控制在4轮内，只有可复现问题需要修复验证时追加。
4. 浏览器检查当前页面导航、确认单关闭/恢复及刷新；不重绘页面、不生成新样稿。
5. 修复可复现问题，运行受影响测试；结果写入本文件。未执行的检查明确留空，不把旧结果当本轮通过。
