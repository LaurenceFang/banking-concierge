# 可用性补齐路线图

2026-10-15。用户认可将整轮走查发现纳入规划，第一批仅联系人和模拟服务管理。其余为已记录的后续需求，不等于本轮全部实施。新增交互先审样稿，再写前端；四入口、侧栏、字体、聊天布局保持。

| 批次 | 能力 | 用户能完成的事情 | 依赖/边界 |
|---|---|---|---|
| A 当前 | 联系人管理 | 新增、搜索、编辑、移除；转账/AA/定时共用；办理中添加后返回原表单 | SPEC23；同名可区分，历史不随编辑改写 |
| A 当前 | 模拟服务管理 | 自建服务、商户、价格、取消规则；编辑/移除；自由加入或移出方案；真实模拟下单与退款 | SPEC23；摆脱两商品白名单，保留旧订单 |
| B | AA扩展 | 临时参与者、指定金额/比例分摊 | A包含仅姓名的联系人；单次临时对象与非均摊在B完成，分摊合计等于总额 |
| B | 账单整理 | 分类、标签、备注修正；手工收支；商户/类别检索；自导入记录更正及批次撤销 | 银行原始流水不改；手工记录不改变银行余额 |
| B | 订阅与识别 | 自建订阅记录、金额/周期/续费提醒；候选确认、纠正、忽略；依据显示真实账单行 | 手工记录不等于接入商户合同；保留用户修正 |
| C | 预算与复核 | 月总额、分类额度、剩余/超额提示；异常标记已核对或继续处理 | 先稳定账单分类与统计口径 |
| C | 安排复用 | 自定义名称、复制、模板、未执行任务改期、重复安排；跨业务计划汇总 | A先去除新增服务的生日专用命名；模板/重复/日历后补，改期需重新确认 |
| C | 账户管理 | 别名、默认收付款账户、预留来源详情；扩展模拟账户管理 | 模拟账户管理不等于真实开户；账户余额不能作为普通表单任意编辑 |
| C | 对话与通知 | 搜索、删除聊天；同一事项汇总进度，异常突出，通知直达对象与原对话 | 删除聊天不取消业务；保留置顶/最近结构 |
| D | 理财体验 | 收藏、自选比较、按金额查看费用/可用时间、订单返回原对话 | 保留受控产品目录，不提供随意创造收益率的用户按钮 |

共用原则：从当前页面就能补齐缺少的对象；添加和本次选用分开；保存后保留表单与原对话；移除目录项不抹掉历史；不为每组能力新增一级导航。识别结论应允许确认、纠正和忽略。

先完成A并实际使用，再根据反馈安排B/C；创新对照实验和比赛材料与可用性完善分别记录，不将预设链路通过等同于整张路线图完成。不做hash校验、dry-run或大型证据包。
