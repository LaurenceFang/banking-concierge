# 联系人与模拟服务管理 SPEC

日期：2026-10-15。状态：用户已认可四格样稿并授权实施，前端medium，整体界面保持；新增对象须实际走通业务。完整后续需求见[SPEC22](22-可用性补齐路线图.md)。

## 1. 目标与范围

用户可在办理途中添加自己的联系人与模拟服务，并立即继续原事项。新增对象必须可实际参与模拟收付款、下单、取消退款；不能只修改前端数组。保存刷新/重启后仍存在。

当前实现限制已核对：Recipient必须绑定bank_accounts；WorkflowCatalogItem已有表，但商品参数仍受CATALOG白名单限制，商户账户通过静态MERCHANTS查找。实施时需一起解除这些固定映射，复用原账本、任务与退款服务，不换框架。

本轮：联系人增查改移除、姓名级AA联系人、共享选择器；服务增查改移除、动态模拟商户、方案加减项、通用安排名称。暂不做真实银行账号接入、真实商户、联系人导入、多账号联系人、非均摊AA、重复任务和模板。

## 2. 保持现有整体界面

- 四入口与二级导航不增加页签。收付款右上增加低调“管理联系人”；收款人字段旁“添加联系人”，AA旁“添加参与者”。
- 我的安排的服务区旁增加“添加服务”“管理服务”。目录管理与本次方案选用是两个不同动作。
- 管理/编辑占用现有单右侧槽位：列表→编辑→返回列表，不叠加第二个侧栏或多层弹窗。保留可调宽度上下限、关闭、返回入口；暂时隐藏聊天时保留原会话和输入。
- 沿用正文14.5px、标题16px、文楷/新晰黑、灰绿底色、细实线。管理行只放姓名/名称、必要摘要及低调操作。窄屏沿用单面板覆盖逻辑。
- 保存按钮：从选择位置进入用“保存并选用”，独立管理用“保存”。关闭未保存表单提示是否放弃；保存失败保留输入、定位字段，不凭超时显示成功。
- 正在确认业务时，必须先返回修改再更改关联对象，避免同时编辑和确认。管理对象本身不新建聊天，也不发主对话通知；业务预览/执行才沿用原对话回执。

## 3. 联系人

### 字段与身份

- 联系人：稳定id、姓名(必填1–40字)、备注(0–120字)、可选的模拟收款资料、启用状态和版本。
- 基础联系人只需姓名/备注，可用于AA，不要求银行卡号。AA显示“仅AA参与”；即时/定时转账选择器中显示“补充收款信息”而不是无声消失。
- 模拟收款资料：模拟银行名称和账户尾号4位；不收集真实完整卡号。填写后可用于即时/定时转账。尾号只是展示，不作为身份或资金路由主键。
- 服务端创建独立模拟对手方身份/结算账户供既有模拟付款路径使用；其固定演示余额来自明确的demo初始化配置，不纳入当前用户资产，也不由模型设置。只填姓名的AA联系人同样能走完现有模拟付款，不伪装为真实银行卡连接。
- 同名允许；列表显示备注及银行/尾号（有资料时），调用以id为准。完全相同的名字/备注/收款资料再次保存时提示已有对象，不反复造账户。
- 编辑姓名/备注不换资金路由；修改收款资料生成新的账户绑定版本。既有已确认安排继续使用确认时的身份/账户快照，不能让未来付款静默转给新账户。

### 操作

搜索覆盖姓名、备注、银行和尾号。保存后自动选中新联系人，保留金额、时间、AA参与者和原对话；跨三个办理入口及模型查询立即可见。AA本轮仍均摊，新增人后重算只读份额；已确认AA不事后加人改账，需另建请求。

移除提示“从联系人列表移除，历史交易保留”；未引用者可删除，已引用者仅退出可选列表，底层引用保留，不额外设计归档中心。未来已确认任务不自动取消；提示仍有几项安排并提供查看。旧的未确认预览引用对象被编辑/移除后失效，要求重新核对。重复保存使用请求标识避免超时重试创建两人。

## 4. 模拟服务

### 字段与执行

服务名(1–60字)、模拟商户(1–60字，可新填或选择已有)、单价(人民币正数且最多两位小数)、单位(默认份)、取消规则（订单确认后可取消退款／确认后不可取消）。附简短说明可选，避免自由文本规则被当执行程序。

商户与结算账户持久化，新增商户自动创建独立模拟结算账户。新服务走统一模拟适配器，具有报价、下单、订单查询及按规则取消/退款；不宣称接通外部商家。去除商品ID白名单和仅限两商户的执行分支，故障配置仍仅用于隔离测试。

单位数量1–5沿用现有约束，本轮每个方案最多10种服务；界面显示上限。预览报价服务端计算。用户可调选取顺序，预览及执行遵循该顺序；原鲜花/蛋糕默认顺序保留。新增服务不强制归到“生日”：方案名称可填写，空值默认“给某人的服务安排”，旧生日任务标题保持。

### 编辑、移除与本次方案

- 保存并选用：新服务进入本次方案，默认1份；其余对象、预算、时间、数量和聊天保持。
- 编辑价格/商户/取消规则更新版本，使相关未确认预览失效。已确认订单/定时安排使用原报价及规则快照，不能追溯涨价或改变退款条款。
- 从本次方案“移除”只减去该项，服务目录保留；从“管理服务”移除是退出以后可选目录，两种按钮说明不同。
- 已确认事项仍可查询和处理原订单；目录移除不删商户结算账户、订单、付款或退款记录。内置演示服务也可移除，重启seed不得把它们重新激活。
- 新服务必须至少完成一次正常模拟扣款和一次按规则取消退款；不可取消服务明确提示真实支出保留。

## 5. 拟定接口与接线

以下是实施契约，尚未存在的接口不能标成已完成。

| 接口 | 用途 |
|---|---|
| GET /api/contacts?query= | 搜索联系人、用途能力及显示信息 |
| POST /api/contacts | 保存联系人，携带client_request_id |
| PATCH /api/contacts/{id} | 根据当前version编辑，冲突返回可读提示 |
| DELETE /api/contacts/{id} | 从可选目录移除并返回未执行任务数量；历史保留 |
| GET /api/workflow-services?query= | 搜索启用服务及版本 |
| POST /api/workflow-services | 新建服务及必要的模拟商户映射 |
| PATCH /api/workflow-services/{id} | 编辑当前版本 |
| DELETE /api/workflow-services/{id} | 移出目录，保留已确认引用 |

已有find_recipients、任务联系人接口、workflow catalog读取改为查询同一存储，避免两份列表。模型继续只查对象与准备业务预览；首版不额外加一套模型直接删除目录的工具。用户说添加时可引导打开相应表单；保存对象后原对话可直接使用。先复用HTTP保存路径，不额外消耗DS完成表单操作。

迁移保留现有联系人ID、账户绑定、商品ID、订单和会话引用；历史显示使用快照，新增字段有兼容默认值。动态商户账户查询代替静态常量；版本检查仅围绕实际编辑冲突，不引入hash体系。

## 7. 实施顺序与验收

用户已认可样稿，本轮按上述次序完成实现，前端medium；检查结果及当前边界见[SPEC24实施结果](24-联系人与模拟服务管理实施状态.md)。

验收只聚焦新增用户路径：

1. 新姓名AA联系人保存后可选、模拟付款真实入账；补收款资料后同一人可普通/定时转账。
2. 编辑、同名消歧、移除、刷新与重启；三入口一致，历史不变，seed不恢复已移除对象。
3. 第三个自定义服务保存后可实际预览、组合、扣款、取消退款；移除方案项与目录项效果分开。
4. 服务改价/联系人变更后旧未确认预览不能执行；已确认定时任务不追溯变价或改收款账户。
5. 关闭管理面板、保存失败重试、返回原页不丢表单/对话；键盘可进入编辑、关闭后焦点返回，字段错误可读。
6. 桌面与窄屏验证新增面板，回归原转账、AA、定时、鲜花蛋糕流程即可；优先确定性测试，少量真实DS检查共享查询。无hash检验、dry-run、大型证据包；不重复全量压力测试。
