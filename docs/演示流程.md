# 银小二演示流程

本文件是可重复演示的操作提纲，实际完成边界见SPEC30及后续验收结果。所有账户、资金、商户和订单均为模拟。不在用户日常演示库反复试单，验收使用独立数据库。

## 主线：一件事可以问清、修改、办完

1. 新建对话：“用日常借记卡给伴侣安排一束生日花和一个蛋糕，各一份，预算500元，确认后立即开始，先给我确认单。”核对目录花199、蛋糕129、合计328。若目录不同，使用当前真实目录，不硬背金额。
2. 追问：“这个安排失败能退款吗？”回答区分未确认无款可退、确认后依实际可取消订单退款、待退款不等于到账；确认单应保留。
3. 改口：“蛋糕不要了，花保留，其他不变。”右侧显示服务变化及328→199，对象/预算/账户保持。也可点继续修改，用1元预算演示失败保留输入，再取消修改。
4. 点击确认安排。应只有花单，不应把旧蛋糕也下单；订单已确认不代表配送。查看回执与实际净支出。
5. 另开对话：“以后木棉咖啡都归为工作支出。”查询规则确认；新增符合条件的CSV记录再看分类。用“这笔归为餐饮”说明单笔修正不会自动泛化。演示完可明确删除规则。

## 六场景补充展示

| 场景 | 入口与动作 | 必须解释的结果 |
|---|---|---|
| 转账 | 给张伟转100元，先消歧银行尾号，再核对确认 | 同名不能猜；预览未付款 |
| 账单 | 收支明细整理分类；导入包含重复/错误行的CSV再撤销该批 | 仅撤新增，历史重复和银行流水保留 |
| 理财 | 在风险档案自己选择五项答案，再比较可用产品、预览小额申购 | 受理和持仓结算不同；可用工具实际返回T+1日期 |
| 卡片 | 选择日常借记卡冻结，再解锁 | 卡片渠道限制不等于冻结存款账户 |
| 订阅 | 解释停止代扣与取消会员，再准备对应操作预览 | 个人记录/候选不等于商户合同 |
| 联动 | 使用上方主线；失败退款用独立故障验收实例 | 失败可退范围由原订单决定，重试不重复下单 |

## 演示前检查

通过启动脚本安装锁定依赖并构建；确认后端健康、DS已配置、目录存在、数据库模式与实际一致。没有PG或模型接口时明确说明，不用录制内容冒充实时成功。不要在展示中出现密钥、调试堆栈或内部请求标识。

主线演示控制在约4分钟，余下时间讲实现、对照结果和限制；独立小样本成绩必须说明样本规模，不能说已验证真实银行或所有用户。
